## 几条关键事实（都实测过）

### 转移通路（双向通）

`POST /api/items/transfer`，请求体 `{ ids: number[], transferAll: boolean }`，
`ids` 是 `PlayerItem.Id`。响应 `{ success, numTransferred, failed }`。

- C# 把 id 拼成 `["PI", id, "", "", "", false]` 交给 `ItemTransferController`，
  与旧 WebView2 路径**同一个控制器**。
- 它把物品序列化成 CSV 写进 `CsvLocationOutgoing`（**不是直接写存档**），
  由注入游戏的 hook 读取；然后把 `StackCount` 置 0 由 `Update` 删记录。
- ⚠️ **失败时也返回 HTTP 200**（`{success:false, error:"…"}`）。前端必须判
  `success` 字段，只看 `res.ok` 会把"转移失败"显示成"已转移 0 件"。
- ⚠️ 「转移到任意 Mod」会让控制器弹 `StashPicker` 模态框（必须 UI 线程），
  所以**开启该设置时 HTTP 转移直接返回明确错误**，不会半路崩。

### 列表自动刷新（B2）

`ws://127.0.0.1:3031/ws`，服务端 → 客户端单向。数据库一变就广播：

| 消息 | 触发 |
|---|---|
| `itemsChanged` | 拾取 / 转移 / 重新解析 / 改 `hideSkills` |
| `maintenance` | 维护任务的进度（含百分比与阶段名） |
| `notification` | 后端主动提示（对应 C# 的 `IUserFeedbackHandler`） |

- ★ **只发轻量信号，数据仍走 REST** —— 不沿用旧的 `IOMessage` 枚举
  （那套是喂旧 Preact 前端的，新前端从没消费过）。理由见 `03-目标架构.md` §4.3。
- 广播点：`CsvParsingService.OnItemLooted`（**拾取走的是这个**）、
  `ListviewUpdateTrigger`、`DatabaseLoadedTrigger`、HTTP 转移成功后。
- 前端 `connectLive()` 自动重连；**断连期间回退到每 4 秒轮询**。
- ⚠️ 已知限制：改动**已有**物品（属性重算、改名）不会触发广播。

### 维护操作在网页上

加载游戏数据库 / 配置 / 更新项目统计三个操作，
进度通过 `maintenance` 消息推送，期间查询被拒（503）+ 整屏遮罩。

- 「清除数据库」**故意没搬**：它做的事「加载数据库」第一步就做了，
  却能制造一个"物品还在、但没名字没属性"的界面。后端端点保留但无入口。
- 配置因为浏览器**拿不到文件夹路径**，改成粘贴路径 + 后端校验。
- 细节 → [`11-备份与恢复.md`](./11-备份与恢复.md) 与 `05-实施计划.md` §6。

| **排序** | ✅ | **2026-09-13 升级并搬到工具条**：`sortBy` = 入库时间（默认，新→旧）/ 品质（传奇在前）→**等级降序**→名称 / **等级降序**→品质→名称 / 名称→品质→等级。SQL 由后端 `PlayerItemDaoImpl.BuildOrderBy` 拼（品质用 `CASE Rarity` 映射成权重，因为库里的 `Epic` 其实是传奇）。旧的 `orderByLevel` 仍接受，但前端不再用 |
| **`GET /api/filters/options`** | ✅ | 品质 / **槽位分组** / 职业 / 比较符 / 分组复选框 / 属性下拉 |
| **过滤面板 + 高级搜索** | ✅ | **颜色即逻辑**：黄 = 与、绿 = 或。圆角色块（未选阳刻 / 选中阴刻）+ 直角「清除」；高级搜索是搜索框**右边**的图标按钮 → **居中模态**（**顶部自带搜索框** + 类型/稀有度/职业/物品属性 + 数值 / 等级 / 时间）。★ **两者是两套东西**：过滤面板实时生效、高级搜索是"搜索条件"（草稿态，点「完成」写回搜索条件，**不动过滤器**） |
| **Mod / 硬核切换** | ⏸ | **暂不做**（2026-09-12 决定）——它牵动数据出口 + 工具条 + 分页语义 + 转移四处，见 [`13-后端待办与计划.md`](./13-后端待办与计划.md) §3 |

- ★ **属性数值过滤不是新写的**：`PlayerItemDaoImpl` 早就实现了
  `Filters`（属性存在性）与 `StatValueFilters`（数值），只是新前端没接、也没有可选项接口。
- ★ **过滤器的定义在后端**（`Services/Filters/FilterCatalog.cs`）：
  照搬旧 WinForms 面板的 4 组（伤害 / 持续伤害 / 抗性 / 杂项），
  每个复选框对应哪些 stat 字段、哪些支持数值，都由后端说了算——
  前端不再抄一份映射，避免"勾了火焰抗性却按别的字段过滤"这种难查的错。
- ⚠️ **Minimal API 默认用 System.Text.Json，不接受字符串枚举**：
  `{"operator":"GreaterOrEqual"}` 会直接 **400 且响应体为空**。
  已在 `WebServer.Start()` 打开枚举名支持（只影响请求绑定，响应仍走 Newtonsoft）。
- ⚠️ 槽位清单**写死**在 `StatTranslator.SlotTranslator`，**不能**查库：
  `DatabaseItemStat_v2` 里 `stat='Class'` 实测有 **175** 个值，
  混着容器、可破坏物、怪物、药水等非装备类别。
- 接口形状、字段含义、选项结构见 `03-目标架构.md` §4.5.1 / §4.5.2；
  **实测命令**（PowerShell 片段 + 两个坑）见 `04-开发环境.md` §9.7。

### 当前运行环境的要点（容易踩坑）

1. **agent 与仓库都在 WSL**，Windows 只当构建靶机 → `04-开发环境.md` §1
2. **Windows 侧验证 HTTP**：WSL 访问不到 Windows 的 `127.0.0.1:3031`，
   要用 PowerShell 发请求 → `04-开发环境.md` §9.4
3. **跑 Debug 还是 Release**：Debug 用隔离的 `userdata-test.db`（空库），
   验证真实数据要用 **Release** → `04-开发环境.md` §9.5
4. **不能从 UNC 路径运行 exe**：`\\wsl.localhost\...` 会**静默失败**，
   要复制到 Windows 本地再跑 → `04-开发环境.md` §9.6
5. **改前端后要部署到「两处」**：`WebUI-next/build/` 既要拷进 `storage/`
   （浏览器真正读的），**也要**拷进程序目录的 `iagd-release/webui/`——
   `IAGrim.exe` 启动时会拿 `webui/` 覆盖 `storage/`（修"原版 IA 覆盖前端"用的
   `FrontendDeployer`），只拷 storage 的话**程序一重启就白改了**（2026-09-14 实测）。
   两处都先删 `assets/`，否则旧哈希文件会堆积。
   ⚠️ 重新编译后端、覆盖 `IAGrim.dll` 前必须先停 IA（运行时会锁住 dll/exe）。
6. **不要打开 `C:\Program Files\IAGD\IAGrim.exe`**：它会把旧前端解压覆盖到
   共用的 `storage/`（见上方「一个必读的坑」）。我们的构建在
   `C:\Users\jyl96\iagd-release\`。
