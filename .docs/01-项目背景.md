## 1. 游戏：恐怖黎明（Grim Dawn）

| 项目 | 说明 |
|---|---|
| 类型 | 动作角色扮演游戏（ARPG），与《暗黑破坏神 2》《流放之路》同类 |
| 开发商 | Crate Entertainment（美国独立工作室） |
| 引擎 | 基于《泰坦之旅》的引擎发展而来 |
| 正式发布 | 2016 年（Steam，AppID **219990**） |

### 与本项目相关的游戏机制

- **双职业系统**：角色可选两个职业组合，装备词缀与技能加成组合极多。
- **品质分级**：白（普通）→ 黄（魔法）→ 绿（稀有）→ 蓝（史诗）→ 紫（传说）。
- **词缀（Affix）**：绿色装备由前缀 + 后缀组合生成，可产生"双绿"极品。
  **因此同类物品之间属性差异极大——"对比"是核心需求。**
- **储物箱（Stash）**：分角色个人箱和**共享箱（Transfer Stash）**，容量有限。
  **这是 IA 要解决的核心痛点。**
- **硬核模式**：角色死亡即永久删除，因此玩家对存档备份极敏感。
- **模组支持**：官方支持自定义 Mod，会产生不同的物品数据库。

> 社区参考：[Crate 官方论坛的 IA 主题帖](https://forums.crateentertainment.com/t/tool-grim-dawn-item-assistant/30491)

## 2. 软件：Grim Dawn Item Assistant（IA）

### 2.1 它解决什么问题

共享箱放不下几百上千件装备，玩家又舍不得扔。IA 给游戏**外挂了一个无限容量的仓库**：

1. 玩家把物品丢进游戏内的共享箱；
2. IA 检测到存档变化，把物品"取走"存进自己的 SQLite 数据库；
3. 需要时在 IA 界面搜索 → 点 Transfer → 写回游戏共享箱。

物品在游戏里**不是真实存在的**，但全部属性（词缀、种子、镶嵌物、变量数值）完整保存，
取回时与原件一致。

> **因此 IA 界面本质上是一个"装备数据库检索器"——界面效率直接决定使用体验。**
> 这也是本项目要重做界面的根本原因。

### 2.2 主要功能

| 功能 | 说明 |
|---|---|
| 物品存储与取回 | 核心：无限仓库 |
| 物品检索 | 按名称、品质、槽位、等级、词缀、数值区间过滤 |
| 收藏图鉴 | 统计物品是否拥有过、套装收集进度（分软核/硬核） |
| 角色存档备份 | 定时备份角色存档 |
| Buddy 共享 | 与好友共享物品列表 |
| 游戏数据解析 | 解析游戏 `.arz` 文件以识别物品属性 |
| Mod 支持 | 为不同 Mod 分别维护物品数据库 |

### 2.3 它怎么"骗过"游戏

1. **注入 DLL**：向游戏进程注入 `ItemAssistantHook_x64.dll`。
2. **状态侦测**：DLL 通过 Win32 消息告知"箱子是否打开、玩家在哪"。
   IA 必须确认"玩家已离开箱子区域"才敢动手，否则可能损坏存档。
3. **文件交换**：物品真正的搬运通道是共享箱存档文件（`transfer.gst`）。
4. **数据解析**：预先解析游戏物品模板数据库，把二进制记录翻译成"名称 + 属性列表"。

> 技术细节见 [`02-现有架构.md`](./02-现有架构.md)。

## 3. 这份代码的来历与定位

| 项目 | 说明 |
|---|---|
| 上游主仓库 | `marius00/iagd`（原作者 Marius） |
| 本仓库 | `https://github.com/Aa-arun/iagd` —— **Aa-arun fork 出来魔改自用的版本** |
| 官网 | <https://grimdawn.evilsoft.net>（上游发布的成品） |
| 当前分支 | `master`，工作区干净，**fork 后尚未做实质改动** |

### 3.1 这是一个自用分支，不必顾虑上游

这一点决定了大量取舍：

- ❌ 不需要兼容上游、不需要考虑 PR、不需要遵守上游的代码风格。
- ❌ 不需要保证向后兼容（通信协议、配置格式都可以改）。
- ❌ 不需要担心"改动太大以后合不回上游"。
- ✅ 可以为了自己顺手做激进重构，包括换掉整个技术路线。

**唯一需要照顾的**是使用者自己的使用体验，以及已有的物品数据库（多年积累，不能丢）。

### 3.2 代码现状

fork 之后代码本身的形态（**非本 fork 的改动**）：

- 前端宿主是 **WebView2**，不是 CefSharp。但命名空间与类名仍保留历史名字
  （`IAGrim.UI.Misc.CEF`、`CefBrowserHandler`）——**看到 CEF 按 WebView2 理解**。
- 目标框架 **.NET 10**（`net10.0-windows`）。
- 前端是 **Preact** + TypeScript + Vite 6（不是 README 里写的 React）。

> ✅ 仓库根 `README.md` 描述的是老架构（CefSharp），是**上游开发者忘记更新**，与本 fork 无关。

### 3.3 运行平台

**本项目只在 Windows 上使用。** 上游提供 Linux（Steam Proton）方案，
但使用者只在 Windows 玩游戏，因此 `LINUX.md` 与相关适配**本项目不需要考虑**。

## 4. 我们要做什么

### 4.1 使用者背景

使用者是 **FPGA 工程师**，熟练使用 VSCode / Linux，**没有软件开发经验**。
本项目具有双重目的：

1. **实用目的**：把 IA 的界面改成自己顺手的样子。
2. **学习目的**：借此了解软件开发（版本控制、构建、依赖、前端框架、调试）。

**对协作方式的影响**：

- 解释要从原理出发，术语顺手解释一句。
- 优先"改动小、见效快"的路径，便于建立正反馈。
- 不为"工程优雅"引入重型框架或复杂工具链。
- 配套教学文档：[`07-教学-软件工程.md`](./07-教学-软件工程.md)

### 4.2 目标

| 优先级 | 目标 | 状态 |
|---|---|---|
| **P0** | **重做装备显示界面**：提供多种可切换的展示样式 | 设计中 |
| ~~P1~~ | ~~隐藏没用的功能~~ | ✅ 已自动解决：重做即"不实现" |
| ~~P2~~ | ~~美化 WinForms 控件~~ | ✅ 已消失：外壳整个去掉 |

**已定的技术路线**：后端服务化 + 系统浏览器访问 + 前端用 **React** 重做，
通信 **REST + WebSocket**，最终去掉 WinForms 与 WebView2，只留托盘图标。

> 详见 [`03-目标架构.md`](./03-目标架构.md)。

### 4.3 约束

1. **功能行为不能坏。** 物品搬运、数据库、游戏解析的结果必须与现在一致。
   后端**架构**可以改（这正是要做的事），但**行为**不能变。
2. **已有数据不能丢。** 物品数据库是多年积累。
3. **每步改动都提交 git**，保证可回退。
4. **优先能立刻看到效果的路径。**

## 5. 术语表

| 术语 | 含义 |
|---|---|
| **Stash / 储物箱** | 游戏内仓库；**Transfer Stash** 指账号级共享箱，是 IA 的搬运通道 |
| **Transfer** | IA 界面的"取回物品"操作 |
| **Affix / 词缀** | 装备的前缀、后缀，决定附加属性 |
| **MI** | Monster Infrequent，特定怪物掉落的专属绿装 |
| **Component / Materia** | 镶嵌物 |
| **Augment** | 附魔 |
| **Buddy** | IA 的好友共享功能 |
| **HC / SC** | Hardcore（硬核）/ Softcore（软核），两套独立数据 |
| **WebView2** | 微软的嵌入式浏览器控件（Edge 内核），现有实现用它显示物品列表 |
| **Preact** | React 的轻量替代品，现有前端用它 |
| **React** | 主流前端框架，**新前端将用它** |
| **Vite** | 前端构建工具，提供开发服务器与热更新 |
| **WinForms** | .NET 的 Windows 桌面界面框架，现有外壳用的就是它 |
| **REST** | 基于 HTTP 的接口风格（GET/POST 等） |
| **WebSocket** | 全双工长连接，用于服务端主动推送 |
