## 1. 进程模型：三个东西在协作

```
┌───────────────────────┐       注入 DLL        ┌───────────────────────┐
│    Grim Dawn.exe      │ ◄───────────────────  │     IAGrim.exe        │
│      （游戏本体）      │                       │  （.NET 10 WinForms） │
│                       │ ── Win32 消息 ──────► │                       │
└───────────────────────┘                       └───────────────────────┘
          │                                                 │
          │  共享箱存档文件 transfer.gst                     │  SQLite 数据库
          └─────────────────────────────────────────────────┘
                    （物品真正的搬运通道）
```

| 角色 | 职责 |
|---|---|
| **IAGrim.exe** | 主程序：界面、数据库、物品搬运、游戏数据解析 |
| **ItemAssistantHook_x64.dll** | 被注入游戏进程，只做"侦察"：报告箱子是否打开、玩家位置、云存档状态 |
| **transfer.gst** | 游戏共享箱存档文件，物品实际的读写通道 |

**关键点**：物品数据**不通过 DLL 传递**，而是通过读写游戏存档文件交换。
DLL 只负责回答"现在动手安全吗"。

> 注入必须发生在游戏启动约 45 秒后（等游戏世界构建完成），否则可能崩溃游戏。

## 3. 界面外壳：WinForms + WebView2

### 3.1 一个命名陷阱

代码里到处是 `CEF` / `Cef` 字样（`IAGrim.UI.Misc.CEF`、`CefBrowserHandler`），
但**实际用的是 WebView2**，不是 CefSharp。这是迁移时留下的历史名字。

> 看到 CEF/CefSharp 字样时，按 WebView2 理解。
> 仓库根的 `README.md` 也还在写 CefSharp——那是上游作者忘记更新，与本 fork 无关。

### 3.2 主窗口结构

```
MainWindow（Form）
├── tabControl1（TabControl）
│   ├── tabPageItems    "Items"       ← 内嵌 SplitSearchWindow
│   ├── tabPageOnline   "Online"      ← 备份 / 云同步设置
│   ├── tabPageSettings "Settings"    ← 常规设置
│   └── tabPageMods     "Grim Dawn"   ← Mod 数据库管理
└── statusStrip（状态栏：状态文本 + 版本号）
```

### 3.3 Items 页的布局

```
┌──────────────────────────────────────────────────────────────┐
│ 搜索框 [____]  □按等级排序  [品质▾] [槽位▾] [Mod▾]  [等级区间] │ ← WinForms 原生控件
├───────────────┬──────────────────────────────────────────────┤
│               │                                              │
│  过滤器面板    │            WebView2                          │
│  （职业/技能/   │      （物品列表，前端渲染）                    │
│   数值过滤）    │                                              │
│               │                                              │
└───────────────┴──────────────────────────────────────────────┘
   ↑ _mainSplitter（可拖动分隔条）
```

布局靠**手工试凑的硬编码负坐标**（如 `Location = new Point(-8, -3)`）对齐，
这是改造中要一并清掉的技术债。

> ★ **这块过滤面板的去向**（2026-09-12）：它的**逻辑**（哪个复选框对应哪些 stat 字段、
> 哪些支持数值过滤）已经原样搬到后端 `IAGrim/Services/Filters/FilterCatalog.cs`，
> 并通过 `GET /api/filters/options` 交给网页；**界面本身还没在新前端做**。
> 也就是说旧面板一旦删掉，能力不会丢，缺的只是新 UI。
> 详见 [`09-高级搜索.md`](./09-高级搜索.md) §6 与 [`03-目标架构.md`](./03-目标架构.md) §4.5.2。

### 3.4 两层导航

界面里同时存在**两套导航**，是"乱"的重要来源：

| 层 | 位置 | 项 |
|---|---|---|
| WinForms | 窗口顶部 TabControl | Items / Online / Settings / Grim Dawn |
| 网页内 | `components/header/index.tsx` | Items / Collections / Help / Components / Discord / Patreon |

其中网页导航的后三项是**跳转外部网站**（官网、Discord、Patreon）。

## 4. ★ 前后端通信（理解现有系统的关键）

### 4.1 两个方向、两种机制

| 方向 | 机制 | 特点 |
|---|---|---|
| C# → 前端 | `webview.ExecuteScriptAsync("window.message({...})")` | 异步推送 |
| 前端 → C# | `chrome.webview.hostObjects.sync.core.<Method>()` | **同步阻塞**调用 |

前端在 `App.tsx` 的 `componentDidMount` 里挂载 `window.message` 函数接收消息。

### 4.2 C# 暴露给前端的方法（`JavascriptIntegration.cs`）

| 方法 | 作用 |
|---|---|
| `TransferItem(id[], transferAll): string` | 转移物品，返回 `{success, numTransferred}` |
| `RequestMoreItems(): void` | 请求下一页搜索结果（无限滚动） |
| `RequestCollectionData(): void` | 请求收藏图鉴数据 |
| `GetItemSetAssociations(): string` | 物品套装归属关系 |
| `GetBackedUpCharacters(): string` | 已备份角色列表 |
| `GetCharacterDownloadUrl(char): string` | 角色存档下载地址 |
| `GetTranslationStrings(): string` | 全部界面翻译文案 |
| `SetClipboard(text): void` | 写入剪贴板 |
| `OpenURL(url): void` | 用系统浏览器打开链接 |
| `SignalReady(): void` | 前端初始化完成，C# 开始投递积压消息 |
| `DismissNumericFilterBanner(): void` | 用户已确认数值过滤引导条 |

### 4.3 C# 下发给前端的消息（`IOMessageType`）

| 值 | 名称 | 含义 |
|---|---|---|
| 0 | `ShowHelp` | 跳到帮助页并带搜索词 |
| 1 | `ShowMessage` | 弹出通知条 |
| 2 | `ShowCharacterBackups` | 切到角色备份页 |
| 3 | `SetState` | 通用状态（见下） |
| 4 | `SetAggregateItemData` | 图鉴汇总表 |
| 5 | `SetItems` | **搜索结果**（核心） |
| 6 | `SetCollectionItems` | 图鉴数据 |
| 7 | `ShowModFilterWarning` | "有 N 件物品被 Mod 过滤隐藏" |
| 8 | `UpdateCloudIconStatus` | 某物品的云备份图标更新 |
| 9 | `UpdateItemStats` | 某物品的真实属性（延迟加载） |

`SetState` 的子类型（`IOMessageStateChangeType`）：
`ShowCloudIcon` / `DarkMode` / `HideItemSkills` / `GrimDawnIsParsed` / `FirstRun` /
`EasterEggMode` / `IsLoading` / `GdSeasonError` / `ShowNumericFilterBanner`

### 4.4 三个关键设计点

1. **消息积压队列**：WebView2 未加载完时，C# 把消息压入 `_initializationQueue`，
   等前端调用 `SignalReady()` 后统一投递。
2. **延迟批量更新**：`UpdateItemStats` / `UpdateCloudIconStatus` 在前端进队列，
   每 6 秒批量应用。因为同步期间每秒可能产生几百条事件。
3. **分页 + 无限滚动**：`ItemPaginationService` 只发前若干条，
   前端滚到底部时调 `RequestMoreItems()`。

## 5. 数据存储

| 项 | 说明 |
|---|---|
| 数据库 | SQLite（`Microsoft.Data.Sqlite` + NHibernate 作为 ORM） |
| 访问模式 | 所有 SQL 通过 `ThreadExecuter` 在**单一专用线程**串行执行（SQLite 并发限制），调用方"异步 + 等待" |
| 分层 | `*DaoImpl` 实现接口 → `*Repo` 包装（加线程调度） |
| 玩家数据 | `%AppData%/Local/IAGD/`：settings、日志、`storage/`（含图标资源） |

### 6.3 样式体系

**所有颜色定义在 `src/style/index.css` 的 `.App`（明）与 `.App-dark`（暗）两个类下**，
组件 CSS 只引用变量。这是现有前端做得最好的部分，**改造时应当保留这套思路**：

```css
.App      { --item-background: #dcd7ca; --item-color-epic: #6f26bd; ... }
.App-dark { --item-background: #171614; --item-color-epic: #a638ff; ... }
```

明暗主题由 C# 通过 `SetState / DarkMode` 消息下发。

### 6.4 ★ 现有布局的问题诊断（"为什么丑"）

关键数值来自 `containers/ItemContainer.css`：

```css
.items .item      { width: calc(30% - 20px); margin: 10px; padding: 20px 20px 65px;
                    border-radius: 15px; }
.item .text       { padding-left: 75px; }              /* 给 68×68 的图标让位 */
.item-icon-container { min-width: 68px; min-height: 68px; }
```

| 现象 | 成因 |
|---|---|
| 一屏可见物品太少 | 固定宽度 `30%` → 一行只有 3 张卡片；底部还预留 65px 放"Transfer"链接 |
| 无效空间大 | 图标 68×68 固定 + `padding-left: 75px` 强制正文右移；卡片 15px 圆角 + 20px 内边距 |
| 信息密度低 | 每条属性独占一行、行距宽松；属性不分主次全部平铺 |
| 无法横向比较 | 卡片宽度一致但不共享列，视线要在不同卡片的随机高度间跳跃 |
| 多副本表达笨拙 | 同一物品多份只多一个 "(N)"，却占同样大的卡片 |

> ✅ 已由使用者确认，与实际情况相符。

### 6.5 图标资源

- 界面 UI 图标（banner、chest、金币、云同步标记等 39 个）**不在 git 里**（`WebUI/src/static/` 已被 `.gitignore` 排除），需从 IA 的 `storage\static\` 复制过去。该目录在**用户数据目录**（`%LOCALAPPDATA%\EvilSoft\IAGD\storage\static`），**不在** `Program Files` 下。
- 开发模式下 `vite.config.ts` 有中间件把 `/static/` 映射到 `src/static/`。
- 非嵌入模式（浏览器）下物品图标走 `http://static.iagd.evilsoft.net/img/<icon>` 远程加载。
  ⚠️ **实测（2026-09-11）该服务返回 403**（`Nothing to see here`）。本地有全部 4573 个图标，开发时改用 `tools/devapi` 的 `/img/` 端点提供，见 [`04-开发环境.md`](./04-开发环境.md) §8。

## 7. 现有实现里值得保留的知识

即使前端重做，以下几样是"已踩过的坑"，不要重蹈：

| 内容 | 位置 | 为什么保留 |
|---|---|---|
| 数据模型 `IItem` / `IStat` / `ICollectionItem` | `src/interfaces/` | 后端决定的，照搬 |
| 品质着色规则与配色 | `src/style/index.css` 的 CSS 变量 | 已调好的配色 |
| 属性分组语义 | `headerStats` / `bodyStats` / `petStats` | 后端决定的 |
| 翻译机制 | `src/translations/EmbeddedTranslator.tsx` | 与后端 `GetTranslationStrings` 配套；**内置约 45 条英文降级文案** |

**不保留**：`components/Item/` 与 `containers/ItemContainer.css`——这正是要重做的部分。
