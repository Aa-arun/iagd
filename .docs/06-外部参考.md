## 1. grimtools.com — 装备 hover 详情（★ 重点待调研）

**参考页面**：<https://www.grimtools.com/calc/2JLrQnDZ>

### 1.1 为什么要参考它

这是我们目前已知**最贴近需求**的现成效果：在一个 build 展示页面里，
**鼠标悬停在装备上会弹出详细数据面板，并且面板可以滚动**。

正好对应我们的 P0 需求——把详细信息从"默认平铺在卡片上"改为"hover 时才出现"，
而且解决了一个已知难题：**双绿 MI 有 20+ 条属性，普通 tooltip 装不下**。
grimtools 既然能滚动，说明它没有用简单的 tooltip 方案。

### 1.2 已知信息

| 项 | 内容 |
|---|---|
| 站点性质 | 社区做的《恐怖黎明》build 模拟器 / 物品数据库，非官方（作者 Dammitt） |
| 观察到的行为 | hover 装备 → 显示详细数据面板 → **面板内容可滚动** |
| 数据来源 | 它自己维护的游戏数据 |

### 1.2.1 ★ 技术栈调研结果（2026-09-11，已确认）

抓取页面源码后确认，**它是一个传统的 jQuery 项目，不是现代前端框架**：

```html
<script src=/common/js/thirdparty/jquery.min.js></script>
<script src=/common/js/thirdparty/jquery.history.min.js></script>
<script src=/common/lib/select2/select2.full.min.js defer></script>
<script src=/db/itemdb/itemdb.js?1789114529></script>
<script src=/db/itemdb/db.js?1789114529></script>
<link rel=stylesheet href=/db/itemdb/itemdb.css?1789114529>
<link rel=stylesheet href=/common/shared/common.css?5f06e66f82a8>
```

| 它用的 | 说明 |
|---|---|
| **jQuery** | 直接操作 DOM，2010 年代的主流写法 |
| **jQuery History** | 前端路由（URL 切换） |
| **select2** | 下拉搜索框插件 |
| **手写 CSS** | 不是 Tailwind / CSS-in-JS，是传统 CSS 文件 |
| **服务端渲染** | 页面内容直接在返回的 HTML 里 |

**图标方案**：把游戏图标打包成 **CSS 精灵图**，逐个用 `background-position` 定位。
CSS 里还带着每个图标的真实像素尺寸，例如：

```css
.itemdb-items_gearweapons_melee2h_bitmaps_a01_axe2h001{background-position:-2144px 0;width:32px;height:128px}
```

> 这个尺寸信息其实就是"物品占几个格子"的答案来源，将来若做图标网格可以参考。

### 1.2.2 ★ 结论：能抄什么，不能抄什么

| 能借鉴 | 不能直接抄 |
|---|---|
| ✅ **CSS 样式**：配色、间距、布局、tooltip 外观 | ❌ **JS 逻辑**：jQuery 的 DOM 操作与我们选定的 React 组件模型完全不同，抄过来必须全部改写 |
| ✅ **HTML 结构**：类名组织、层级关系，作为设计参考 | ❌ **高级搜索实现**：它是服务端查询 + jQuery 渲染 |
| ✅ **交互设计思路**：hover 怎么弹、滚怎么滚、怎么定位 | ❌ **图标/素材资源**：版权归属游戏厂商与站点作者 |
| ✅ **"分类筛选"的信息架构**（品质/槽位/类型怎么组织） | — |

> **一句话**：grimtools 是**设计参考手册**，不是**代码库**。
> 看它的效果和 CSS，用我们自己的 React 重写。

### 1.3 待调研的问题（等前端动手时再查）

- [ ] hover 面板在它那里是 **DOM + CSS** 还是 **canvas**？
      （按 jQuery + 服务端渲染推断，大概率是 DOM，但**尚未验证**）
- [ ] 弹出定位是怎么处理的：跟随鼠标？固定在某个角落？靠近屏幕边缘会自动翻转？
- [ ] 面板的"可滚动"是怎么实现的：固定最大高度 + `overflow: auto`？
      有没有自定义滚动条？鼠标滚轮事件是否被拦截？
- [ ] 属性文本的样式怎么组织：颜色、分组、缩进规则（**看它的 CSS 就能抄到**）
- [ ] 有没有做"与当前装备对比"的功能？怎么呈现的？

### 1.4 与我们的处境的差异（重要）

| 维度 | grimtools | 本项目（新前端） |
|---|---|---|
| 前端技术 | jQuery + 服务端渲染 | **React + Vite**（见 `.docs/03-目标架构.md`） |
| 类型 | 在线网站 | 本地 C# 服务 + 系统浏览器 |
| 数据 | 全在页面里（服务端渲染） | 通过 **REST + WebSocket** 从 C# 取 |
| 页面上的物品数量 | 一个 build 的**几十件**装备 | 可能一次检索出**上千件**自己拥有的装备 |
| 交互重点 | 展示一个既定的 build | **检索、筛选、对比**自己的仓库 |

**关键判断**：

- hover 面板本身是**纯前端技术**，与数据从哪来无关，**思路可以参考**。
- 但因为技术栈不同（jQuery vs React），**代码不能直接搬**，要用 React 重写。
- **性能是重点差异**：我们的列表可能有上千件，快速划过时反复创建/销毁详情面板
  会造成卡顿。grimtools 一个页面只有几十件，不存在这个问题。
  → 我们的实现要考虑复用 DOM（固定一个面板实例，只换内容），而不是每次 hover 新建。

### 1.5 调研方法（备忘）

1. 打开页面，hover 一件装备，右键"检查"，看弹出的 DOM 结构。
2. 在 Elements 面板观察类名，反推它的 CSS 组织方式。
3. 在 `Sources` / 网络面板看它加载了哪些 JS 库。
4. 尝试把它的 CSS 规则抄下来做个小 demo 验证。
5. 结论写回本文档，供 `.docs/03-目标架构.md` §6.3（hover 详情面板）的决策使用。
