# 08 · 属性翻译

> 本文记录**物品属性怎么从数据库变成可显示文本**——调研结论与实现方案。
> 结论已实现于 [`tools/devapi/`](../tools/devapi/)（"简单层"），前端在 A5 会用到。
> 调研日期 **2026-09-11**。

---

## 1. 问题：属性翻译不只是"翻译"

数据库里一件物品有 **33 条** stat 行，但游戏里只显示 **7 条**。
以「费坦面具」为例：

| 该显示（7 条） | 不该显示（26 条，引擎内部字段） |
|---|---|
| `characterLife=500`、`defensiveProtection=1326`、`defensiveElementalResistance=28`、`characterOffensiveAbility=18` … | `actorHeight`、`armorMaleMesh`、`dropSound`、`physicsFriction`、`maxTransparency`、`scale`、`templateName` … |

所以这件事要做**三件**事，缺一不可：

1. **筛选**——33 条里挑出该显示的
2. **翻译**——stat 名 → 中文模板
3. **填值**——把数值填进模板的占位符

---

## 2. ★ 关键发现：stat 名就是模板的 key

`StatTranslator/StatManager.cs:596` 是这么写的：

```csharp
foreach (var tag in tags) {
    translationTable[tag] = _language.GetTag(tag);   // ← stat 名 == 模板 key
}
foreach (var elem in stats.Where(m => translationTable.Keys.Contains(m.Stat))) {
    result.Add(new TranslatedStat {
        Text   = translationTable[elem.Stat],
        Param0 = (float)Math.Round(elem.Value, 1, MidpointRounding.AwayFromZero),
        Param3 = elem.TextValue,
    });
}
```

**stat 名本身就是模板的 key**，同名直取。这让"翻译"这一步退化成一次查表。

实测「费坦面具」的 7 条属性，**7/7 全部命中同名模板**：

| stat | 模板 | 结果 |
|---|---|---|
| `characterLife` | `+{0} 生命` | +500 生命 |
| `characterOffensiveAbility` | `攻击能力 +{0}` | 攻击能力 +18 |
| `defensiveElementalResistance` | `{0}% 元素抗性` | 28% 元素抗性 |
| `defensiveProtection` | `{0} 护甲` | 1326 护甲 |

## 3. 翻译的三个来源

这是最容易搞混的地方：**游戏内翻译并不覆盖属性模板**。

| 层面 | 来源 | 在 IA 里的去向 |
|---|---|---|
| **游戏内容**（物品名、技能名、任务、教程） | 游戏 `C:\Grim Dawn\resources\Text_XX.arc` | 解析后存 **`ItemTag` 表**（19,352 条） |
| **属性模板**（`+{0} 生命`） | ❌ **不在 `ItemTag` 表** | IA 的 `IAGrim/Resources/translations/zh.txt` |
| **英文模板** | ❌ 不在任何文件 | 硬编码在游戏引擎；IA 用 `StatTranslator/EnglishLanguage.cs`（858 行）复刻 |

四条实测证据：

1. `Text_ZH.arc`（2.3 MB）里**能**搜到 `offensivePierceRatioMin` 和「穿刺转换」——游戏自己的汉化确实含属性模板
2. 但 `ItemTag` 表里 **0 条**含 `{0}` 占位符（19,352 条中）——IA 没把属性模板提取进去
3. `Text_EN.arc` 只有 **471 KB**（中文 2.3 MB）——**英文内置在引擎里**，不靠文件
4. `zh.txt` 共 807 条 = **515 条 `iatag_*`**（IA 界面文案）+ **235 条含占位符的属性模板**

运行时的合成顺序见 `IAGrim/Parsers/Arz/LocalizationLoader.cs:80-85`：

```csharp
var dataset = new Dictionary<string, string>(gameTags);      // 先放游戏解析出的 tag
if (_tagsIa != null)
    foreach (var tag in _tagsIa) dataset[tag.Key] = tag.Value;  // IA 的 zh.txt 覆盖上去
```

即：**游戏 tag 提供物品名，`zh.txt` 提供属性模板**。

> 注释里也写明了这点（同文件 68-70 行）：
> "The bundled IA translation file is layered on top, **it only carries IA's own UI strings**."

## 4. 实测覆盖率

对 66 件真实玩家物品（3,450 条 stat）统计：

| 项 | 数量 |
|---|---|
| 涉及的不同 stat 种类 | 225 |
| **有同名中文模板**（可直接翻译） | **70 种 / 688 条** |
| 无同名模板 | 155 种 |

**"19%" 这个比例具有误导性**：3,450 条里绝大多数是元数据，而那 688 条正是"该显示的属性"。

更重要的是——**那 70 种有模板的 stat，没有一条是元数据**（已逐条核对）：

```
characterLife → +{0} 生命          defensiveFire → {0}% 火焰抗性
characterStrength → +{0} 体格      offensiveCritDamageModifier → +{0}% 暴击伤害
defensiveProtection → {0} 护甲      characterRunSpeedModifier → +{0}% 移动速度
```

所以筛选规则可以很简单且安全：**有同名模板 → 显示**。

## 5. 分层实现

### 5.1 已实现：简单层

位置 [`tools/devapi/server.mjs`](../tools/devapi/server.mjs) 的 `translateItemStats()`。

逻辑：
1. 取该物品的全部 stat 行
2. stat 名在 `zh.txt` 里有同名模板 → 保留，否则跳过（元数据）
3. `val1` → `param0`（四舍五入 1 位，对齐 C# 的 `AwayFromZero`）
4. `TextValue` → `param3`（供 `{3}` 占位符，且**能翻就翻**：`class08` → 死灵法师）

`headerStats` / `bodyStats` 的划分复刻 C# 的 `MapSimpleHeaderEntries` 白名单
（8 项核心属性：护甲、穿刺转换、技能相关）。

**实测效果**：66 件物品 **688 条属性**全部翻出，耗时 **0.11 秒**。

```
费坦面具 (Blue Lv94)
  1326 护甲 · 所有技能+1 · +500 生命 · 攻击能力 +18
  28% 元素抗性 · 20% 生命抗性 · 30% 减速 抗性
```

### 5.2 未实现：特殊层

`StatManager` 还有 **28 个 `Process*` 方法**（1005 行）处理这些情况：

| 类别 | 例子 | 对应方法 |

| **技能修饰** | `augmentSkillLevel1..5`、`augmentMasteryName1..3` | `ProcessSkillModifierStats` |

实测**需特殊逻辑的 stat 只有 124 种**，且集中在上述几类。

> 简单层**不影响** P0 目标：布局、卡片、列表、图标、品质配色、基础属性都只依赖已实现的字段。

## 6. 与前端的关系

约定沿用 C# 的**"模板 + 参数"**设计，而不是后端拼好字符串：

```ts
export interface IStat {
  text: string;      // 模板，如 "+{0}% 攻击速度"
  param0: string;    // 数值
  param3: string;    // 技能名 / 职业名，供 {3}
  // …
}
```

**为什么不在后端拼好**：同一个模板可复用；前端能按需给数值加样式（高亮、百分比着色），
这在 ARPG 的属性展示里很常见。

前端负责把 `paramN` 填进 `{N}`。相关类型见
[`WebUI-next/src/model/stats.ts`](../WebUI-next/src/model/stats.ts)。

## 7. 若要把特殊层也做完

需要复刻 `StatTranslator/StatManager.cs` 的对应方法。建议顺序：

1. **技能修饰**（`augmentSkill*`）——玩家物品里出现最多的一类
2. **伤害转换**——机制清晰，模板已就绪
3. 其余按实际遇到的空属性补
