## 1. 自动备份（不需要任何设置就会跑）

| 项 | 事实 |
|---|---|
| 触发 | `MainWindow` 装配时 `new BackgroundTask(new FileBackup(...))`；那个后台线程**每 10ms** 调一次 `FileBackup.Update()` |
| 实际频率 | **每 30 分钟一次**——节流在 `FileBackup.Update()` 里（`_timer.ElapsedMilliseconds > 1000*60*30`），首次调用会立即备份一次 |
| 备份内容 | **三样**：① 游戏角色存档（`GlobalPaths.SavePath` 下递归）② **IA 的全部物品**（`export.ias`）③ 一个 `YES THIS FILE IS SUPPOSED TO BE SMALL.txt` 说明文件 |
| 位置 | `%LOCALAPPDATA%\EvilSoft\IAGD\backup\` |
| 命名 | `{DateTime.Now.DayOfWeek}.zip` → **`Monday.zip` … `Sunday.zip`** |
| 保留策略 | 一周 7 个文件名轮换。**同一天的多次备份会覆盖同一个文件**，所以实际是"最近 7 天各一份" |

> ★ **备份里既有角色存档也有物品**。日志里对应两行
> `Backing up characters..` / `Backing up items..`（`FileBackup.cs`）。
>
> 所以即使 IA 的数据库整个坏掉，`export.ias` 里的物品也还在。

### 1.1 自定义备份位置

`FileBackup.Backup()` 最后**无条件**执行 `Backup(GlobalPaths.BackupLocation, false)`——
也就是说**默认位置的备份始终会做**，关不掉。自定义目录是在此之外**额外**加一份：

```
paths.Add(customPath)                                    // ← 只在开启时才加
foreach (path in paths) Backup(Path.Combine(path, "EvilSoft", "IAGD"), forced);
Backup(GlobalPaths.BackupLocation, false);               // ← 无条件
```

典型用法：把自定义目录指向 OneDrive / Dropbox 的同步文件夹，这样备份会跟着上云。

## 2. 设置里那两项到底是什么意思

网页设置页的「备份」区块有两个控件。**它们的名字有误导性**，这里澄清：

| 界面文案 | 真实字段 | 实际含义 |
|---|---|---|
| **压缩备份** | `LocalSettings.BackupCustom` | ⚠️ **不是"要不要压缩"**——备份**永远**是 zip。它是"**额外**再存一份到下面的目录" |
| **备份目录** | `LocalSettings.BackupCustomLocation` | 上面那个"额外一份"放哪 |

> 名字的来历：旧界面上这个控件叫 `cbZipBackups`、tag 是 `iatag_ui_zipbackup`
> （"Zip backups"），中文翻成了"压缩备份"。那是**原作者的命名**，与实际行为不符。
> 网页版沿用了这个 tag 的译文。
>
> **更好的叫法**：「额外备份到自定义目录」。

### 2.1 ⚠️ 没有"备份 URL"这个选项

设置里**没有任何 URL 字段**。数据库中与备份有关的只有三个：

- `BackupCustom`（bool）
- `BackupCustomLocation`（string，**目录路径**）
- `OptOutOfBackups`（bool，是否退出原作者的云备份）

旧界面上那个"Define"链接弹的是 **`FolderBrowserDialog`（选文件夹）**，
写进 `BackupCustomLocation`：

```csharp
using var folderBrowserDialog = new FolderBrowserDialog();
if (folderBrowserDialog.ShowDialog() != DialogResult.OK) return;
_settings.GetLocal().BackupCustomLocation = folderBrowserDialog.SelectedPath;
```

所以如果记忆里有个"填地址"的框，那是**填目录路径**，不是 URL。

> 另有一个 `LocalSettings.BackupNumber` 字段，但**全仓库没有任何使用者**——死字段。

## 3. ★ 恢复：目前是个缺口

**IA 只自动备份，不自动恢复。**

恢复的实现在 `IAGrim/UI/Popups/ImportExport/`（一个 WinForms 弹窗）：
它能读 `.ias` / `.gds` / `.zip`（`IsValid()` 专门检查"zip 里有没有 `.ias`/`.gds`"，
帮助链接指向 `HelpType.RestoreBackup`）——**正好就是自动备份产出的那种 zip**。

**但那个窗口随旧界面删除后已经没有入口了**（见 [`10-界面解耦.md`](./10-界面解耦.md)）。

### 后果

误删物品或数据库损坏时，**目前没有任何界面能把 `export.ias` 导回来**。
备份文件在磁盘上躺着，但用不上。

### 出路

搬到网页。**浏览器不能选文件在这里不是障碍**（见下一节）：

| 操作 | 网页怎么做 |
|---|---|
| 从备份恢复 | 后端列出 `backup/*.zip` 供选择——文件本来就在本机，**连上传都不用** |
| 导入外部 `.ias`/`.gds` | `<input type="file">` 上传，POST 给后端 |
| 导出 | `GET /api/items/export?format=ias|gds` 触发浏览器下载 |

## 4. Web UI 到底能不能弹窗选文件 / 文件夹

**能弹，但"能拿到什么"差别很大。** 这是浏览器安全模型决定的，不是实现选择。

| 需求 | 能力 | 说明 |
|---|---|---|
| 选**文件**（读内容） | ✅ **可以** | `<input type="file">`，或 Chromium 的 `showOpenFilePicker()` |
| 选**保存位置** | ✅ **可以** | Chromium 的 `showSaveFilePicker()`；退化方案是直接触发下载 |
| 选**文件夹** | ⚠️ **能选，但拿不到路径** | `<input type="file" webkitdirectory>` 或 `showDirectoryPicker()`（Chromium）。返回的是**目录句柄 / 文件列表**，**没有** `C:\...` 这样的绝对路径 |
| 拿到文件在磁盘上的**完整路径** | ❌ **不行** | 浏览器的沙箱**故意**不给。这是为了防止网页探测用户磁盘结构 |

> File System Access API（`showOpenFilePicker` / `showSaveFilePicker` /
> `showDirectoryPicker`）只在 **Chromium 内核**（Chrome / Edge）可用，
> 且要求 **secure context**——`http://127.0.0.1` 算，所以本地服务没问题。
> 但这些 API **都不返回绝对路径**，`showDirectoryPicker` 尤其如此
> （社区里反复有人问"怎么拿到目录路径"，答案是拿不到）。

### 对本项目的含义

| 场景 | 结论 |
|---|---|
| **导入物品**（`.ias`/`.gds`） | ✅ 浏览器弹窗完全够用——我们只需要**内容**，不需要路径 |
| **导出物品** | ✅ 触发下载即可 |
| **从备份恢复** | ✅ 后端列出 `backup/*.zip`，连文件选择都不需要 |
| **配置 Grim Dawn 安装目录** | ❌ 这条**需要路径字符串**（后端要拿它去读 `Items.arc`），而浏览器给不了 |

**"配置"有三条路**：

1. **手填路径**（当前做法）——能用，但要用户会找路径
2. ★ **后端弹原生文件夹对话框**——HTTP 请求触发、`Invoke` 到宿主的 UI 线程执行
   `FolderBrowserDialog`。**能拿到真实路径**，体验和旧界面一致。
   宿主窗口虽然不可见，但消息循环在（见 [`10-界面解耦.md`](./10-界面解耦.md)），所以可行
3. `showDirectoryPicker` —— **不可行**，拿不到路径

> **结论：想让"配置"也变成弹窗选择，走第 2 条路**（后端弹原生框），
> 而不是指望浏览器 API。这需要在 HTTP 层与 UI 线程之间做一次 marshal。
