## 1. ★ 详情直接用**游戏原样导出的 tooltip**

这是本页最重要的一个决定。

| 数据源 | 内容 | 用不用 |
|---|---|---|
| `JsonItem.replicaStats` | **游戏原样导出的完整 tooltip**：带 `^X` 颜色代码、套装、授予技能、伤害转换行、需求行，顺序与游戏内一致 | ★ **用它** |
| `JsonItem.headerStats` / `bodyStats` | IA 自己从 `DatabaseItemStat_v2` 翻译拼出来的 | 仅在 `replicaStats` 为空时兜底 |

**为什么**：

- 游戏通过 `ItemReplica` 把它生成的 tooltip **原样**给了 IA，IA 存进库。
  全部 64 件实测物品都有，最多的一件 **81 行**。
- 从 `DatabaseItemStat` 重新拼一套不可能对齐——实测这批物品的
  `headerStats` **全是空的**，`bodyStats` 最多 4 条（而且只有技能加成那种）。
  转换行、套装层级、授予技能这些更是拼不出来。

代价是它**只能是文本行**（不是结构化数据），但"接近游戏效果"这个目标
本来就要求逐行还原，结构化反而是障碍。

### 1.1 `^X` 颜色代码

游戏在 tooltip 文本里嵌 `^` + 一个字母的颜色标记（`^-` 表示恢复默认）。
代码 → 属性类型的对应写在游戏的汉化包里（`tags_ui.txt` 开头那张
"物理伤害—棕色——{^E}"的表）。

⚠️ **具体 RGB 没有公开来源**——它硬编码在游戏的 `records/game/gameengine.dbr`
里（Crate 论坛的 "Text Color Codes?" 一帖确认了这点）。
所以 `global.css` 里那套 `--tt-*` 是**按颜色名 + 游戏观感定的**，
目标是"看起来像"，不是逐像素一致。

### 1.2 按使用者要求做的三处偏离

游戏原版有几个行为在"物品库"这个场景下没意义，已改掉（实现在
`ReplicaStatList.tsx` + `ReplicaStatList.css`）：

| 游戏里 | 库里 | 为什么 |
|---|---|---|
| 技能名带英文（`黑死病 (Black Death)`） | **只显示中文** | 使用者不要英文。游戏把英文包在 `^s` 里 → CSS `display:none`；另一种旧格式（`type=81`）没有 `^s`，按"含技能等级的行"删括号 |
| 非本职业技能灰掉 | **统一颜色** | 游戏按**人物职业**算，但库里的装备不属于任何人物 |
| "需要 玩家等级/灵巧"是红色 | **普通色** | 那是和人物属性联动的提示，库里没有"当前人物" |

> ⚠️ 删英文括号时**不能无差别删**：普通属性里的 `(OA)` `(DA)` `(AS)` `(CDR)`
> 是缩写，必须保留。所以只对"技能等级"行动手。

> ⚠️ 同一个代码在不同语境下语义不同：`^F` 在属性行是"活力伤害"（桃红），
> 在技能行是职业名（`^g<^F神秘^g>`）。所以"技能行统一颜色"必须**按行判断**，
> 不能只靠 CSS。

## 2. 物品名的颜色

### 2.1 基础名：按稀有度

`.item-detail__name` / `.item-card__name` 上挂 `qualityClass(item.quality)`
（`quality-legendary` 等），色值在 `global.css` 的 `--q-*`。

### 2.2 词缀：**我们自己维护词缀表**

> ★ 这一节是 2026-09-12 改过的。原来靠"游戏当前汉化包 + 重新加载数据库"，
> 使用者要求改成**程序自带**一份，不依赖它。

`WebUI-next/src/model/affixes.json` 是**内置的词缀表**，从使用者提供的汉化包
**全目录**提取（503 条）：

| 来源文件 | 条数 |
|---|---|
| `tags_items.txt` | 385 |
| `aom/tagsgdx1_items.txt` | 54 |
| `foa/tagsgdx3_items.txt` | 47 |
| `fg/tagsgdx2_items.txt` | 10 |
| `tags_ui.txt` / `foa/tagsgdx3_ui.txt` | 7 |

其中 `^g`（稀有绿）344 条、`^y`（魔法黄）144 条、带推荐标记 `☆` 的 100 条。

**名字由前端组装**（`composeItemName`）：

```
^g恒定☆·   +   保护者 胸铠   +   ^y·雄鹰☆
  前缀绿         基础名（稀有度色）    后缀黄
```

数据来自 C# 新加的三个字段：

| 字段 | 内容 | 来源 |
|---|---|---|
| `prefixTag` / `suffixTag` | 词缀的 tag 名（如 `tagPrefixB001_Sh_A`） | `Tags` 里按 record 查 `lootRandomizerName` |
| `nameCore` | **纯基础名**（如 "保护者 马裤"） | 见下面的坑 |

⚠️ 任一例词缀查不到时**整体回退**到 C# 拼好的 `item.name`——宁可两个词缀都用
游戏文本，也不要显示成缺一半的半成品。

⚠️ **这个表是静态数据**：游戏加了新词缀就要重新提取一次。

#### 踩到的两个坑

1. **提取的正则写窄了**。DLC 的 tag 形如 `tagGDX1PrefixB104_WpnMelee1h_A`
   ——`Prefix` 前面还有 DLC 代号，所以 `tag(?:Prefix|Suffix)` **一条都匹配不到**，
   整整漏了 118 条，导致几件装备只能回退。正确的是
   `tag\w*(?:Prefix|Suffix)\w*`。
2. **基础名不只是 `itemNameTag`**。游戏的名字是
   `prefix + quality + style + name + suffix`（汉化包第一行的
   `{%_s0}…{%_s4}` 模板）。"保护者 马裤"里 **"保护者"来自 `itemQualityTag`**，
   只拼 `itemNameTag` 会得到光秃秃的"马裤"。改用与 `GetItemName` 相同的模板、
   只是不带前后缀。

> ⚠️ `^y` / `^g` 的样式**按容器限定作用域**：同一个 `^g` 在 tooltip 的职业标记
> （`^g<^F神秘^g>`）里是尖括号的颜色，不能共用一条规则。

## 3. 三种视图

注册在 `WebUI-next/src/views/registry.ts`，**加一行就多一种**（视图只接
`items` + 回调，不碰数据逻辑）：

| id | 名称 | 用途 |
|---|---|---|
| `table` | 分栏列表 | 表格式，关键信息分栏对齐，精确找装备 |
| `compact` | 简洁卡片 | 图标 + 名称 + 关键标签，快速浏览 |
| `compare` | 详细对照 | **完整属性并排摊开**，筛选后比较几件装备 |

`compare` 视图的"同一行以最宽的为准"用 **`align-items: stretch`** 实现
（flex 的默认行为就是同行等高）。**刻意不用 JS 量高度**：那不仅要处理测量
时机，还会撞上"图标加载完高度才变"的时序问题，flex 天然免疫。

### 3.1 布局：只有列表滚动

使用者 2026-09-12 要求"滚动只发生在物品列表那个框里，表头不动"，所以整页
不再是长滚动文档，而是**固定高度的 flex 列**：

```
┌─────────────────────────────────┐
│ header / tabs        flex: none │ ← 不滚
│ 搜索 + 视图工具条     flex: none │ ← 不滚
├───────┬─────────────────┬───────┤
│ 左栏  │ 物品列表         │ 右栏  │ ← 只有列表自己 overflow-y
│(可选) │ (独立滚动)       │(可选) │
└───────┴─────────────────┴───────┘
```

布局层是单独的 `AppShell.tsx`（它要用详情面板的 Context，而 `App` 自己在
Provider 外面取不到）。

⚠️ flex 列里 `.app` 与 `.app__content` 都必须 `min-height: 0`，否则子元素
撑高后 flex 不收缩，**内部滚动会整个失效**（这是 flex 布局的经典陷阱）。

## 4. 交互

### 4.1 详情面板的两种显示方式

工具条上的「详情」下拉框切换，偏好存 `localStorage`：

| 模式 | 行为 |
|---|---|
| `hover`（浮动） | 跟随鼠标浮动，鼠标移开即消失 |
| `docked-left` / `docked-right` | 在左/右侧**固定一栏**。选中了显示选中的，没选中就跟着 hover 走 |

★ 固定栏**不是 `position: fixed`**，而是 grid 的一列、面板是普通文档流元素。
这样它天然位于工具条下方（"不顶头"），且栏宽由**模式**决定、
**与是否选中无关**（"无论是否选中都留空"）。

三种模式在选中/hover 的语义上完全一样，只是定位不同，没有复制逻辑。

⚠️ 有个真实冲突要处理：面板平时是 `pointer-events: none`（否则 hover 时它
会挡住指针、立刻触发 `mouseleave` 导致闪烁），但固定框**必须能滚动**。
而且鼠标从卡片移向右侧面板时会经过空白、离开卡片——按原逻辑内容会被清空，
刚想滚动就没了。所以固定框模式下：**始终接收鼠标事件**，
且鼠标移开卡片时**保留内容**（移到别的卡片上仍会正常换）。

### 4.2 取消选中

- 点面板里的关闭
- 再点一次同一件
- ★ **点任意空白处**（`mousedown`，不是 `click`——拖滚动条/选文字不该触发；
  点在物品卡片上时不取消，那是"改选另一件"）

### 4.3 焦点框

hover 与选中用同一色系、**不同强度**（`--focus-accent` /
`--focus-hover-bg` / `--focus-pinned-bg`）。

用**左侧竖条**而不是只换背景：列表行本来就细，纯背景变化容易被忽略。
竖条的位置**预先用透明边框占好**，避免 hover 时整行内容横向跳动。

### 4.4 「取出」按钮

两种视图里都有，**不必先选中弹详情**。方形、图形化、拟物化——实体感靠
CSS 做：竖向渐变模拟受光、内侧顶部高光 + 外侧投影让按钮浮起、按下时换成
内凹阴影并下沉 1px。

- 就地反馈：成功/失败直接换图标，两秒后复位（取回是"点一下就走"的操作，
  弹面板反而碍事；但失败必须让人看见）
- `stopPropagation`（连 `mousedown` 一起拦）：不能让点击冒泡到卡片，
  否则会顺带选中它
