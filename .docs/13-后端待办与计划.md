## 3. ★ Mod 支持（暂缓）

> **决定（使用者，2026-09-12）：Mod 相关功能先不做。** 本节的目的是**别把已经查清的东西丢掉**。

### 3.1 现状：Mod 不是"过滤选项"，而是"结果集前提"

| 事实 | 说明 |
|---|---|
| `Mod` 的语义 | `PlayerItemDaoImpl.SearchForItems` 里：**空 = 只看非 Mod 物品**（`PI.Mod IS NULL OR PI.Mod = ''`），非空 = `LOWER(PI.Mod) = LOWER(:mod)`。**不是**"不过滤" |
| 硬核同理 | `PI.IsHardcore` / `NOT PI.IsHardcore` 二选一，也不是可选过滤 |
| 旧界面怎么用的 | 工具条上一个下拉，数据来自 **`IPlayerItemDao.GetModSelection()`**：`SELECT DISTINCT IFNULL(mod,''), ishardcore FROM playeritem` —— 注意它是 **"mod + 是否硬核"的组合**，因为两者都是前提 |
| ⚠️ 别搞混 | `GET /api/grimdawn/mods`（`MaintenanceService.GetMods`）返回的是**已安装的 mod**（扫游戏目录），用途是「加载数据库」时选哪个 mod 来解析。**它不能拿来当过滤下拉** |
| 新前端现状 | **没有任何 mod / 硬核选择器** → 界面上只能看到**非 Mod 物品**。玩 mod 的人等于看不到自己的东西 |

后端**数据是现成的**（`GetModSelection()` 一直在），缺的只是把它交出去 + 前端 UI + 转移那一段。

### 3.2 为什么暂缓

不是难度问题，是**改动面**问题——它同时牵动四块：

1. **数据出口**：要新开一个端点（或并入 `/api/filters/options`）返回 `{ mod, isHardcore }` 组合
2. **前端工具条**：加"仓库"选择器；⚠️ 切 mod 是**换前提**，必须重置分页并重查总数（不像普通过滤那样能就地翻页）
3. **硬核**：`isHardcore` 目前也是个前端没暴露的裸布尔。做 mod 时通常要**一起**做"普通 / 硬核"切换，否则硬核玩家的物品照样看不到
4. **转移**：要做到"任意 mod 转移"，得先把 §3.3 的第 3 步做掉

### 3.3 将来要做的三件事

| 步 | 内容 |
|---|---|
| 1 | **后端**：加 `GET /api/filters/mod-selection`（或并入 options），直接复用 `IPlayerItemDao.GetModSelection()`，返回 `[{ mod, isHardcore }]` |
| 2 | **前端**：工具条加"仓库"选择器（非 Mod / 各 Mod，含普通·硬核），切换时**重置分页**；把选中的 `mod` + `isHardcore` 放进 `ItemSearchRequest` |
| 3 | **转移**：把"选目标 mod"从**模态框**改成**数据**——后端先给可选目标列表 → 前端选 → 转移请求带上目标；`ItemTransferController` 加一条"目标已指定"的分支，绕开 `StashPicker`。做完这条，§1 里那处"HTTP 转移被拒绝"就可以撤掉 |

### 3.4 验收标准

- 选某个 mod 后列表只剩该 mod 的物品，`total` 正确，翻页也正确
- 切"普通 / 硬核"能正确切换，且两者互不串
- 切回"非 Mod"能恢复原状
- 开启 `TransferAnyMod` 后，**从浏览器转移不再报错**，物品进到指定 mod 的仓库
