## 1. 高级搜索的图标：自绘

**问题**：使用者给了参考 <https://www.grimtools.com/db/zh/> 的 `id="btn-adv-search"`，并说"直接画还是参考由你决定"。

**查到**：该站被 Cloudflare 挡着——直接抓返回 403，经本机代理（`10808`）再抓仍是 403，拿不到那个按钮的图标。

**决定**：自绘一个内联 SVG：三条带滑块的横杆（"精细调节"的通用符号），颜色用 `currentColor` 跟随主题。

**为什么**：项目不引 CSS 框架、也还没引图标库；为一个按钮添一个图标依赖不划算。而这个符号本身就是通用语义，不需要照抄某个站。

## 2. 品质多选与"1 / 2 个绿色词缀"不兼容

**问题**：`GET /api/filters/options` 的 `qualities` 里 `Green` 出现三次（`prefixRarity` = 0 / 1 / 2，对应旧界面的"稀有 / 1 绿色词缀 / 2 绿色词缀"）。但品质多选走的是 `rarities` **数组**，而 `prefixRarity` 是**单值**——两者没法同时表达。

**决定**：面板里的品质**按值去重**，只留 4 个：魔法 / 稀有 / 史诗 / 传奇。绿色词缀细分**不做**。

**为什么**：checklist 的语义是"这些都要"，而词缀数量是"至少几个"的阈值语义；混在一起会得到"稀有（不限词缀）OR 1 个词缀"这种没有意义的结果。旧界面那个细分是**单选**用途，放进多选面板只会误导。

> 后端字段都还在。将来真要这个细分，应该做成一个独立的阈值控件（"绿色词缀 ≥ n"），而不是品质选项。

## 3. 死代码清理的边界

**问题**：审计出几十个"零引用"的类型，但"零引用"不等于"该删"。

**判据**：**删掉之后会不会有人回来找它。**
- 逻辑**已被取代**（搬到了新地方）或**功能已明确不做**（图鉴）→ 删。
- 只是**暂时没有入口**、但将来要用的实现 → 留。

**按这条线分的结果**：

| 处理 | 内容 | 理由 |
|---|---|---|
| 删 | `UI/Filters/`、`UI/DesiredSkills.*`、`Theme/Firefox/`、`NumericFilterDialog`、`SettingsController` 三件套 | 定义已搬进 `Services/Filters/FilterCatalog.cs`，能力不丢；界面本身已由网页取代 |
| 删 | 图鉴残留（`IItemCollectionDao` / `ItemCollectionDaoImpl` / 两个 Model） | 图鉴页已决定不做 |
| 删 | `SearchController` 的 WebView2 推送通路、`ItemPaginationService`、各事件残留类 | 接收方（旧 Preact 前端）已不存在 |
| **留** | `UI/Popups/ImportExport/`（导入导出**物品**，无入口） | 它是"备份恢复"的**现成实现**，而使用者只是决定**暂缓**那个功能（`11-备份与恢复.md`）。删了要去 git 历史里翻 |
| **留** | `IBrowserCallbacks` 的接口名与 `UI/Misc/CEF/` 位置 | 它还剩两个活方法，且同目录的 `IUserFeedbackHandler` 仍在用。改名要把改动扩散到三个文件，换来的只是"名字好看" |

**顺带结论**：`UI/Misc/CEF/` 这个目录名（CEF = 已删掉的 Chromium 内嵌框架）确实已经名不副实，但它装的东西还在用——留着，等哪天整块都不用了再一起清。

## 4. `headerStats` 全为空：有意抑制，不修

**问题**：`.docs/08-属性翻译.md` 与 `00` 的待办里都记着"`headerStats` 实测全为空，值得查是不是解析侧的问题"。

**查到**：**不是解析问题，是有意的抑制**。
`ItemHtmlWriter.cs:107` 有一句 `skipStats = replicaStats != null`，`:133` 据此把 `HeaderStats`（以及 `PetStats`）置空——因为 IA 采集物品时**游戏已经把完整 tooltip 给过来了**（`replicaStats`），再拿数据库重拼一份只会重复渲染。上游数据其实齐全（`ItemStatService.BuildTags` 已把护甲、生命等填好）。

**决定**：**不修**，从待办里去掉。

**为什么**：这不是缺陷。真正要解决的是另一个问题——"列表里想显示关键属性（护甲/生命）时没有结构化的数值可用"。那应该**在 `ItemHtmlWriter` 里另出一组白名单字段**（或让前端复用已经算好的 `ComputedItemStat`），而**不是**放开那句 `skipStats`——放开只会让详情面板把同一件装备的属性渲染两遍。

> 所以 `00` 里那条待办的正确形态是"列表要不要显示关键属性列"，而不是"headerStats 为什么空"。

## 5. 属性翻译的"前缀变体"缺口：成立，已修

**问题**：属性翻译的规则是"stat 名就是模板 key"。但 `08-属性翻译.md` §5.2 记着一个缺口：有些属性的模板 key 带前缀，例如 `skillManaCostReduction` 的模板其实叫 `customtag_xpac_modif_skillManaCostReduction`。那条记录是针对**已退役的 Node 原型**写的，C# 侧从未验证。

**查到**：**缺口在 C# 侧同样成立**，但成因和当初猜的不一样——
C# 的 `MapSimpleBodyEntries` 是"**白名单**循环 + 同名 `GetTag`"，**没有兜底遍历**：取不到模板就返回空串，属性被静默丢掉。`skillManaCostReduction` 恰好既不在白名单里、也没有同名模板。

**决定**：修。给白名单补上该项，并加一层兜底：同名取不到时再试 `customtag_xpac_modif_<stat>`；同时**过滤掉最终仍取不到模板的项**（否则会渲染出一条空属性）。

**顺带修了一个真 bug**：`StatManager.cs` 里"减少目标伤害"和"降低目标抗性"两个分支的模板**用反了**（对照 `EnglishLanguage.cs:219-220` 可确认）。这个不是缺口，是写错了。

## 6. 后端剩余项的价值判断：三项不做

`13-后端待办与计划.md` §2.2 里有几项，做完调研后判断**不值得做**——理由记在这里，免得下次又翻出来重议。

| 项 | 判断 | 理由 |
|---|---|---|
| **WebSocket 广播盲区**（改动已有物品不触发 `itemsChanged`） | 不做 | 真实场景只有"更新项目统计"，而它**走维护模式**——维护结束时 `WebServer.ExitMaintenance` 已经广播过了。其余触发点要靠后台线程跨服务接线，收益对不上 |
| **预计算滞后**（刚拾取的物品要等后台算完才能被数值过滤查到） | 不做 | 后台每 2.5 秒推进 25 件，窗口很短；要消除它得让拾取路径直接调用预计算并广播，跨三条链路 |
| **`/api/filters/options` 加缓存** | 不做 | **实测 30 ms**（本机 66 件物品）。低频调用，缓存带来的失效问题比省下的时间值钱 |

## 7. `headerStats` 之外：列表的"关键属性"目前没有数据源

**问题**：过滤面板做完后，列表（分栏 / 卡片视图）依然只显示名称、品质、等级，没有"护甲 / 生命 / 攻击能力"这类一眼能扫的数值。

**决定**：本轮**不做**，但把结论留在上面第 4 节和 `13` 里。

**为什么**：这需要先定"哪几个算关键属性"（`03-目标架构.md` §6.2 一直挂着这个待决策），而使用者还没定。没有这个定义，加什么列都是猜。
